# Citizen Journey

Este recorrido describe como debe sentirse DatosEnOrden para una persona que nunca ha usado la plataforma. La experiencia completa debe parecer una unica conversacion con el Estado, no una coleccion de paginas tecnicas.

## Recorrido ideal

```text
Una persona llega desde Google
-> ve el Pulso del Estado
-> encuentra un evento
-> abre la Lectura Documentada
-> consulta el Documento Fuente
-> revisa Evidencia
-> entiende el contexto
-> abre Cronologia si quiere ver evolucion
-> abre Expediente si quiere investigar antecedentes
-> comparte
-> se suscribe o apoya el proyecto
```

## 1. Llegada

La persona no conoce la arquitectura. Inicio debe responder rapido:

- que hace DatosEnOrden
- por que existe
- como empezar

La Home no debe sentirse como dashboard. Debe abrir una conversacion: algo cambio en el Estado, esta lectura lo explica y la fuente se puede comprobar.

## 2. Pulso del Estado

Pregunta principal: que cambio recientemente?

El Pulso no es una lista tecnica. Cada elemento debe mostrar que ocurrio, el tema relacionado, la fuente oficial y una entrada clara: `Entender contexto`. El destino debe ser la Lectura Documentada, no una vista aislada del evento.

## 3. Lectura Documentada

Pregunta principal: que significa este tema?

La lectura debe contener la explicacion suficiente para que la persona entienda el tema sin saltar entre rutas. Documento fuente, evidencia, cronologia resumida, expediente resumido y lecturas relacionadas deben sentirse como secciones de una misma historia.

## 4. Documento Fuente

Pregunta principal: de donde salio esta informacion?

El documento fuente no es un adjunto. Es el respaldo central. Debe estar visible, enlazado y conectado con fragmentos o referencias cuando existan.

## 5. Evidencia

Pregunta principal: donde esta respaldada esta afirmacion?

La evidencia debe aparecer cerca de la afirmacion que sostiene. No debe sentirse como una seccion tecnica al final.

## 6. Cronologia

Pregunta principal: como ha evolucionado este tema?

La cronologia ordena eventos por fecha. No debe repetir resumenes. Cada evento debe decir que ocurrio, cuando ocurrio, que fuente lo respalda y si hay documento relacionado.

## 7. Expediente

Pregunta principal: que organismos y antecedentes estan involucrados?

El expediente es una vista avanzada. La Lectura Documentada debe mostrar un resumen suficiente para que solo investigue mas quien realmente lo necesite.

## 8. Continuidad

Al final de la lectura, la persona debe poder:

- compartir
- recibir futuras lecturas
- sugerir un tema
- apoyar el proyecto de forma discreta

Estas acciones no deben competir con el contenido.

## Reglas de experiencia

- Una pantalla, una pregunta principal.
- Una seccion, informacion nueva.
- Una afirmacion importante, una forma de comprobarla.
- Un evento, una ruta hacia contexto.
- Una fuente oficial, siempre visible.
